# Changelog

All notable changes to USBHawk. Dates are UTC.

## 1.0.2 (2026-11-19)

From the second pass over the same real KAPE collection: the 1.0.1 output was right except for the points below.
Every fix has a regression test built from fictional data (`docs/TESTING.md`, 449 tests).

### Fixed
- **`setupapi.dev.log` times keep daylight saving.** The log is in local time and was converted with the offset in
  force at collection. A New York PC collected in November (EST) had installs from October (EDT) placed an hour late,
  which showed as a ghost "no removal" session one hour after the real one. USBHawk now converts with the host's
  time zone and its DST rules, and falls back to the bias only when the zone is unknown (`details.tz_used`).
- **A slow external disk is still one row in the replay table.** The USB node and disk 6416 events of one plug-in
  were paired only within the same second; an external hard disk logged them 5 s apart and showed as two rows with two
  first-seen alerts. They are now paired within 30 seconds, never two disks or two USB nodes in one row.
- The **Look at first** block under the replay table gives full dates (`at 2020-11-10 12:02:54`, or first to last),
  not just a time of day.

### Added
- **Orphaned volume GUIDs say when the volume was created.** Windows makes time-based GUIDs for removable volumes;
  the `orphaned_device_reference` finding decodes the creation time (`evidence.volume_created`, a lower bound: the
  stamp can run a few minutes early) and notes other
  orphaned volumes stamped in the same second (`evidence.volume_created_with`), which one stick's plug-in cannot explain.

## 1.0.1 (2026-11-18)

Fixes from the first run on a real KAPE collection (a VHDX of a running Windows 10 PC). Every fix has a regression
test built from public samples or fictional data (`docs/TESTING.md`, 438 tests).

### Fixed
- **A damaged chunk no longer costs the whole event log.** A log copied while open (KAPE on a running PC) can hold
  a zeroed chunk; the Security log was dropped entirely with "Invalid EVTX chunk header magic". `sessions`, `tamper`
  and `detections run` now read around damaged chunks and records and warn with the count skipped and read.
  `partition_log_gap` on a damaged Partition/Diagnostic log is low ("may be damage rather than deletion"), not medium.
- **A malformed record no longer stops a file** (`'NoneType' object has no attribute 'get'` on a record with
  `"System": null`).
- **`detections run` judges H2 (off hours) on the host's clock**, as `sessions` does: `--tz` (new on `run`), else
  the time zone in the SYSTEM hive found next to the logs, else UTC with a warning. The first line of the output
  names the zone used. A 07:02 New York connection used to be judged as 12:02 UTC and missed.
- **Disk images given as input print how to mount them.** `--triage case.vhdx` (or `.vhd`, `.E01`, `.dd`, `.raw`,
  `.vmdk`) and `detections run --evtx case.vhdx` print read-only mount steps instead of "folder not found"; any other
  file asks for the collection folder.
- Text from the evidence (device names, volume labels, paths) is shown literally in the tables; square brackets in it
  were read as formatting and could disappear.

### Added
- **Dirty hives are flagged.** When a hive's header sequence numbers differ (newest changes still in `.LOG1/.LOG2`),
  USBHawk warns and suggests `rla.exe`; every `orphaned_device_reference` on a dirty SYSTEM hive carries a caution,
  since the drive connected just before collection can be missing from `Enum` without having been wiped.
- **Logs from `Windows.old` are labelled** "[Windows.old: previous installation]", and `evidence_host_mismatch`
  explains that setup-time names (`WIN-...`) usually come from them.
- **One plug-in, one row.** Windows logs Security 6416 for the USB device node and again for its USBSTOR disk; the
  `detections run` table shows the pair as one row and says so. `alerts.jsonl` still holds both, as a live rule would.

## 1.0.0 (2026-11-17)

First release as a product: a standalone Windows executable, a Python package, a demo kit for every module and a
validation on public real-world evidence.

### Added
- **Standalone `usbhawk.exe`** (PyInstaller, one file, no Python needed) and a **wheel**
  (`pip install usbhawk-1.0.0-py3-none-any.whl`); `python -m usbhawk` works too. `scripts/build_release.ps1` builds
  both, runs the test suite, smoke-tests the exe from the release zip and the wheel in a fresh virtual environment,
  and writes `SHA256SUMS.txt`.
- **Demo kit** (`examples/`): one folder per tool (`sessions`, `tamper`, `detections`, `graph`, `real-evidence`),
  each with demo commands, the output to expect and how to read it. Fictional data for the fleet graph (four hosts)
  and the detections (an insider timeline), generated by `scripts/make_examples.py` from the builders the tests
  use; `sessions` and `tamper` demo on the public sample evidence. Every demo command is run by the test suite.
- `examples/tamper/wiped-host/`: a fictional PC wiped with USBOblivion, written as real Windows files (registry
  hives and an emptied Partition/Diagnostic log) that RECmd and EvtxECmd also read. It raises every tamper finding;
  together with the public samples, every one of the eight findings has a demo.
- `usbhawk detections run --events FILE.jsonl`: replay neutral events (one JSON object per line) through the rules,
  without `.evtx` files.
- `scripts/fetch_demo_datasets.py`: fetch public datasets on demand with hash checks (NIST CFReDS Data Leakage
  case, EVTX-ATTACK-SAMPLES) and prepare a triage folder with 7-Zip; nothing is bundled.
- `docs/GETTING-STARTED.md`, `docs/REFERENCE.md` (moved from the README), and `ideas/` with one file per future idea.
- `docs/USE-CASES.md` (the four use cases on one page, each command run by the tests) and `docs/INTEGRATIONS.md`
  (worked KAPE, Velociraptor and Elastic examples). Each detection hypothesis is explained in
  `docs/hunt-detection-rules.md`: what it means, innocent causes, what to do next.

### Fixed
- `usbhawk graph --runs out device QUERY` (the documented form) ignored the pivot: `--runs` took the pivot words as
  two more run folders. The first `device` / `user` that is not an existing folder now starts the pivot.
- `graph --runs` with a path that does not exist is an error instead of being skipped silently.
- `--config`, `--watchlist` and `--allowlist` with a missing file are errors; a mistyped `--config` used to run with
  the default thresholds without a word.
- `--triage` on a KAPE or Velociraptor collection used the 0-byte `config\RegBack\SYSTEM` (or an older
  `Windows.old` hive) instead of the live hive whenever one was collected, losing the host and every device finding.
  The live hive in `Windows\System32\config` now always wins, and every other copy is printed as `skipped`.
- `detections run --evtx` stopped with a traceback at the first log it could not read (a live log folder without
  administrator rights, a locked or damaged file). Unreadable logs are now listed and skipped; when none can be read
  the error says to run elevated or export the logs with `wevtutil epl`.
- `graph` exports (graph.json, GraphML, Cypher) merged two sticks that share a weak serial into one node, the merge
  `serial_collision` exists to prevent. Their IDs now carry the host when device keys collide.
- `graph ... device` / `user` pivots now name the hosts where the stick was wiped (they have no records left, so no
  row of their own).
- An empty card-reader slot's repeated Partition/Diagnostic "no media" removals became one session each (1,624 on
  one PC). Only a device's first removal can start an end-only session; the rest are counted in a warning. Such a
  session now shows `unknown (removed ...)` instead of `?` / `no-end`.
- Composite USB devices (keyboard/mouse receivers, phones with MTP + ADB) take their class from their interfaces:
  HID and MTP devices were filed as "other".
- A device without a hardware serial shows its Windows-made instance ID as `(none) <id>` in the iSerialNumber column.
- `collect_local.ps1` collects Windows 11's rotated `setupapi.dev.<date>.log` archives too; `expected_artifact_missing`
  looks for the current `setupapi.dev.log`, so archives alone no longer hide its deletion.
- `detections run` ends with a **Telemetry gaps** note naming the hypotheses that could not fire for lack of
  telemetry, and GETTING-STARTED explains how to turn it on (Sysmon, PnP and process-creation auditing).
- H3 (bulk copy) and H4 (archive) no longer count the Recycle Bin `$I` metadata files Windows creates on a stick
  when files on it are deleted, nor System Volume Information (seen on a real PC: they led a 1,195-event H3 alert).
  Files copied into the Recycle Bin folder itself still count. Applied to the Sigma, ES|QL and KQL rules too.
- `detections run` and `detections list` head the hypothesis column `Hypothesis`; a replay ends with a
  **Look at first** block: the alerts by level (high first), each with its first time.
- A mistyped `--triage` folder is reported as not found instead of "no artifacts found".
- Two rules' triage steps (H3, H4) contained an unquoted `: ` and became dicts in the Elastic import; the rule
  validator now rejects any non-text false-positive, response or reference item.
- `evidence_host_mismatch` no longer says a log "comes from another machine" when most of its records are from this
  host (a renamed PC, or one built from an image); it now says the log is mixed. Found on the NIST case.

### Validated
- NIST CFReDS Data Leakage case (Windows 7): both USB sticks of the answer key found with the right serials, user and
  first-connection times; no false tamper findings; no false detections over 2,833 real events. Windows 7 gaps
  (later connections, MBR volume letters, EMDMgmt labels, execution evidence) are documented in `docs/TESTING.md`
  and planned in `ideas/`.
- EVTX-ATTACK-SAMPLES: the real Security 1102 and System 104 records fire H7, with counts matching EvtxECmd.

### Changed
- Clearer table headings, all in UTC: `Connected (UTC)` and `Duration` (sessions), `Source Timestamp (UTC)`
  (tamper), `Event Timestamp (UTC)` (detections), `First / Last Seen (UTC)` (graph pivots); the serial column is
  `iSerialNumber`; every `Why` column is now `Description`. JSON and CSV field names are unchanged.
- The release zip includes `scripts/collect_local.ps1` for live response (`reg save` + `wevtutil epl`).
- The README is a front page (what it answers, sample output, install, demo, how it works, validation); reference
  material moved to `docs/REFERENCE.md`. The package metadata links to the GitHub repository.
- The version has a single source, `usbhawk.__version__`.

## 0.4.0 (2026-11-17)
- Named **USBHawk**: one `usbhawk` command, output datasets and fields `usbhawk.*`, ASCII banner and per-command
  help with examples.
- Module #1 `usbhawk graph`: fleet device graph across hosts, six fleet hunts, device and user pivots, JSON / GraphML /
  Cypher exports.

## 0.3.0 (2026-11-17)

## 0.2.0 (2026-11-16)

  apart from Windows feature-update cleanup; lab-verified against USBOblivion.

## 0.1.0 (2026-11-15)
