# USBHawk examples

One folder per tool. Each one explains what the tool answers, gives copy-paste demo commands, shows the output you
should get, and explains how to read it. Every demo command in these READMEs is run by the test suite
(`tests/examples_demo/`), so what you see is what you get.

| Folder | Tool | Question it answers | Demo data |
|---|---|---|---|
| [sessions/](sessions/README.md) | `usbhawk sessions`, `usbhawk devices` | Which USB sessions look like data exfiltration, and why? | Public sample hives and logs (fetched) |
| [tamper/](tamper/README.md) | `usbhawk tamper` | Did someone wipe the USB evidence, or did Windows clean it up? | A fictional wiped host in real Windows formats (included), plus public samples |
| [detections/](detections/README.md) | `usbhawk detections` | How do we catch it live next time? | A fictional insider timeline (included) |
| [graph/](graph/README.md) | `usbhawk graph` | Where else has this stick been, and who else used it? | A fictional four-host fleet (included) |
| [real-evidence/](real-evidence/README.md) | all | How does it do on a real case? | NIST CFReDS Data Leakage, EVTX-ATTACK-SAMPLES (fetched) |

## Before you start

`usbhawk` is the program itself. There is no `usbhawk` file in the repository root: where it comes from depends on
how you got USBHawk.

| You have | Where `usbhawk` is | How to run the demos |
|---|---|---|
| The release zip | `usbhawk.exe` in the unzipped folder, next to `examples\` | `cd` into that folder and type `.\usbhawk.exe` wherever these pages say `usbhawk` |
| The wheel (`pip install usbhawk-...whl`) | Installed as a command in your Python's `Scripts` folder | Type `usbhawk` from a folder that has `examples\` (a clone, or the unzipped release) |
| A clone of this repository | `.venv\Scripts\usbhawk.exe`, after `pip install -e .` in a virtual environment | Activate the environment in every new terminal (`.\.venv\Scripts\Activate.ps1`), then type `usbhawk` from the repository root |

`python -m usbhawk` works anywhere the package is installed.

The `sessions` demo and part of the `tamper` demo use real public registry hives and event logs. Fetch them once (about 30 MB,
into `tests\data`, never committed):

```
python scripts\fetch_test_samples.py
```

## The fastest tour

```powershell
usbhawk detections run --events examples\detections\insider_timeline.jsonl
usbhawk graph --runs examples\graph\fleet
usbhawk graph --runs examples\graph\fleet device 60A44C41
usbhawk sessions --triage tests\data --tz America/New_York
usbhawk tamper --triage examples\tamper\wiped-host
```

1. An insider's Friday evening, replayed through the detection rules: all eight hypotheses (H1-H8) fire.
2. Four hosts, six fleet hunts: one stick carried data across three PCs, another was wiped on one host but is still
   recorded on another.
3. Everywhere the suspicious stick has been, who used it, and where it was written to.
4. A real Windows 7 host's USB sessions, scored with reasons: a stick reformatted nine times in a day tops the list.
5. A PC wiped with USBOblivion: the tool's own run, the sticks it erased, the emptied Partition log and the deleted
   setupapi.dev.log, told apart from the sticks Windows removed itself during a feature update.

## About the data

Everything included in these folders is **fictional**: hosts `NW-*`, users `NW\j.doe`, `NW\a.smith`, `NW\k.lee`,
`NW\m.ortiz`, invented serials. The `.jsonl` files and the wiped host's registry hives and event log are generated by
`python scripts/make_examples.py` from the same builders the tests use, and a test fails if the files and the
generator ever disagree. The one exception is
`sessions/approved_devices.txt`, which lists a serial from the public regipy sample hives.

Why both kinds? `detections` and `graph` read text (JSONL), which can be written by hand without losing realism.
`sessions` and `tamper` parse binary registry hives and `.evtx` logs, so their demos also run on **real public
evidence**, which proves the parsers handle what Windows actually writes. No public dataset shows a USB wipe,
though, so the tamper demo adds a fictional wiped host written in the genuine formats: its hives are `regf` files
that Eric Zimmerman's RECmd also opens and decodes the same way, and its event log passes EvtxECmd's checksum.
